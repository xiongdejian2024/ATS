# 独立脚本作业

脚本作业属于项目，不需要计划、测试用例或专用结果 JSON。Shell/Python 内容及命令参数在每次运行时冻结，普通进程退出码 0 即成功；非零退出、超时、启动错误与取消分别记录。现有测试报告不包含脚本作业。

## 操作与接口

所有接口使用现有登录认证和 APIResponse.data。项目读取权限控制定义、历史、HTTP/WS 日志与每一段原始下载；写入、运行、取消、人工关闭还要求项目执行权限及目标节点创建人或 system:manage。排队真正领取运行槽时重新检查执行用户、项目权限与冻结节点归属。

- GET/POST `/api/v1/script-jobs`，列表接受 projectId/page/size。
- GET/PUT `/api/v1/script-jobs/{jobId}`。
- GET `/api/v1/script-jobs/nodes?projectId=...` 返回当前有节点操作权限的启用节点与本会话能力。
- POST `/{jobId}/runs` 的 body 为 `{requestId}`。同一请求号返回原执行，跨用户/作业冲突拒绝；请求响应丢失时必须沿用原请求号。
- GET `/{jobId}/runs` 分页历史，GET `/{jobId}/runs/{executionId}` 查看一轮执行。
- POST `/{jobId}/runs/{executionId}/cancel` 持久保存取消意图。
- POST `/{jobId}/runs/{executionId}/resolve` 必须明确传 `confirmedStopped: true`，可附核对说明 reason；只允许 unknown 且仍占槽的执行。
- GET `/{jobId}/runs/{executionId}/logs` 强制有界尾部（tailChars 默认/上限 32768，limit 上限 20）。
- POST `/{jobId}/runs/{executionId}/logs/export` 与现有原始日志快照/分段导出同一协议，body `{}` 或 `{cursor}`；完整语义参见《原始日志有界下载》。
- WebSocket `/ws/script-jobs?token=...&job_id=...&execution_id=...` 支持终态后的晚到日志，消息 `script_job_log` 含 job_id/execution_id/data。初始订阅及每次心跳轮次重新检查读取权限。

定义请求：projectId（仅创建）、name、environmentId、mode（shell/python/command）、script、command、args、workDir、timeoutSeconds。命令模式使用独立 command 与精确 argv 数组，不做 shell 拆分；Shell/Python 使用 script 与可选 args。工作目录为空时使用本轮独立目录；非空时须为 Agent 工作空间相对路径，并在节点拒绝符号链接越界。脚本仍按节点操作系统用户的权限运行，并非操作系统沙箱。

上限：脚本 64 KiB UTF-8；128 个参数，每项 8192 字符；命令 4096 字符、工作目录 500 字符；相关配置 JSON 128 KiB；超时为 1–86400 秒有限数值。节点无需 Git 凭据、Groovy、DSL 或定时配置。Python 使用 Agent 的解释器，POSIX shell 使用 /bin/sh，Windows shell 使用 cmd.exe。

## 执行真相与恢复

TaskQueue 的 kind 为 suite/script。script_job_runs 保存冻结配置与结果；TaskQueue 的 pending/running/terminal 控制所有类型共用的节点容量。Agent 的 ExecutionAdmission 同时限制脚本、套件和旧任务。脚本完成前先停止所属进程组，终态进入共享 durable outbox；云端原子保存退出码结果和队列终态后才 ACK。脚本运行耗时使用单调时钟。

离线节点可提交 pending，不占运行槽。已连接但明确缺少 script_jobs_v1 的 Agent 拒绝新执行；待执行脚本不会挡住可运行的套件。能力属于当前认证 AgentSession，派发使用检查过能力的同一 session，连接替换不转发旧派发。

网络发送不等于开始或完成。派发/取消未确认、断线、控制器重启会显示 unknown 并保留 running 槽；系统不自动重发脚本。每次派发冻结 dispatch_session_id。当前 Agent 中仍存在该 runner 时可跨重连取消，已有 durable terminal 可用新 session 回放。无当前 runner 时，只有仍处于原派发 session 且无执行 marker/目录，才可写禁止执行 tombstone 并确认未启动；跨重连或新空工作空间不能以“缺文件”推断旧执行未开始。已有 accepted marker 而无终态也保持 unknown。

用户核对节点、确认该执行未启动或全部相关进程已停止后，才能人工关闭并释放槽。此结果明确为 unknown/人工关闭，exitCode 为空，记录操作者、时间和说明，不改成成功。之后重新运行使用新 executionId；迟到完成不覆盖人工关闭，迟到原始日志仍保留。

## 日志边界

script_job_log 与 suite 日志共享同一个 Agent SQLite spool、stream ID、连续序号、云端 AgentLogCursor 及批次事务。混合批次中的任何归属/配额错误会整批回滚，不推进 ACK。未确认记录不会删除。终态和日志可独立到达；界面和下载只承诺服务器已接收的快照。

实时内容保留原始正文并显示有界尾部，虚拟列表和重复行折叠只改变展示。原始下载共用 256 KiB 分段、固定记录/结束位置、用户/路径作用域、每段权限检查与缺段错误，不在浏览器构造整个日志 Blob。

## 升级与兼容

先在维护窗口运行 `python scripts/upgrade_script_jobs.py` 查看只读 DDL 计划；核对备份后用 `--apply` 应用 MySQL 增量升级。它创建独立表，添加 kind（历史行默认 suite）和 script_job_id，放宽 suite_id 的非空限制并保持原外键，增加单目标约束。预检关键结构，验证行数与目标约束，重复运行无步骤时才算完成。不会自动删除或重建业务表。

旧 SQLite 的 suite_id NOT NULL 无法安全增量放宽，本工具在任何 DDL 前明确拒绝；新 SQLite 建库与测试支持新模型。现有通用 workspace 升级工具不能替代本迁移，应先完成本脚本迁移。

部署顺序是 schema → 新 controller → 新 Agent → 使用入口。新 controller 保留旧 Agent 的套件功能，但脚本需要本会话能力；新 Agent 连缺少脚本能力的 v2 controller 不启动脚本。旧 controller 不理解新 payload，因此存在脚本运行、未确认终态或脚本日志时不得回滚 controller。Agent 检测到旧 controller 时保留脚本 outbox/spool，不采用旧 socket-send ACK 删除证据。单 controller worker 的现有部署边界不变。

验证仅使用隔离数据库、回环服务与合成 Python/shell 命令，不连接硬件或生产节点。当前自动测试实际覆盖 Python 成功、精确输出、Shell 非零、静默超时、共享套件容量、取消、丢失日志/终态 ACK 重连恢复、同请求幂等、快照下载，以及旧 SQLite 无修改拒绝。真实 MySQL 升级与 Windows 进程树行为仍需在对应隔离环境验证。
