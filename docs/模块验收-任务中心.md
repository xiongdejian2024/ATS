# 任务中心模块验收

## 目标与实现

2026-10-05，按 MeterSphere 的任务管理方式在 ATS 内独立实现 Python 调度，不引入 Java 服务或 MeterSphere 源码。

- 任务目标支持当前项目的测试套、测试计划；计划任务调用 `services.plan_orchestration.start_plan_run`，不重复实现计划编排。
- 支持手动即时入队、五段 Cron、时区、显式启停、下次执行、独立执行历史、取消以及派发异常确认。
- 定时任务创建时一律关闭；修改或启用配置才计算未来的下次执行时间。停用定时器不会取消已创建的执行记录。
- 前端手动触发携带请求号。后端以唯一触发键去重；前端请求失败后重试沿用同一请求号，避免响应丢失导致重复入队。
- Cron 解析和下次时间计算使用现有 Celery 的 `crontab`，数据库采用既有 SQLAlchemy，不添加依赖。
- 所有读取、创建、配置、触发和取消都走当前项目权限；执行目标必须属于当前项目，调度时再次验证执行用户状态和权限。
- 每次触发与对应队列/计划批次在同一数据库事务内创建。到期领取使用条件更新和唯一键；恢复后合并错过的周期为一次触发，不补发停机期间的每一分钟。
- 执行使用现有 `TaskQueue → WebSocket → Agent → XAT` 链路。取消运行中任务需等待节点的真实完成消息，不能直接把未知结果改成取消或成功。

## 挂载契约

1. 导出 `models.task_schedule.TaskSchedule`、`TaskScheduleRun`，通过正式迁移创建新表，不改旧数据。
2. 将 `api.v1.task_center.router` 挂载到 `/api/v1/task-center`。
3. FastAPI 生命周期运行 `services.task_scheduler.scheduler_loop()`，退出时取消协程；`ENVIRONMENT=test` 下默认不启动，测试显式调用 `scheduler_tick`。
4. 前端 `/task-center` 加载 `TaskCenter.vue`。接口适配集中在 `frontend/src/api/taskCenter.ts`。
5. 独立诊断入口 `backend/scripts/task_scheduler_tick.py` 只检查一次到期任务并持久化入队，真正的消息发送由运行中的 ATS API 负责。该入口不创建默认调度，也不自动启用任何调度。

调度周期为 2 秒。定义和运行状态都存数据库，刷新网页或重启后端不会丢失已经保存的任务。计划串行/并行及失败策略由计划模块推进，任务中心只关联计划运行批次。

## 异常处置边界

数据库提交和 WebSocket 写入无法组成跨进程原子事务。本实现不宣称 exactly-once：发送前保存 `dispatching`，发送成功再记 `delivered`，节点既有执行号负责同一 Agent 进程内的重复保护。若服务在此窗口中断，超过 30 秒仍未确认的记录显示“派发待确认”，系统不会自动重派。

用户需要核对节点执行状态；确认该执行未开始或已经停止后，才能通过历史中的“人工确认结束”把记录标为异常结束。这个操作不终止节点进程，也不会制造成功结果。正常离线节点保留排队，恢复连接后继续派发；已停用节点不由任务中心派发。计划目标的同类异常由计划详情中的处置入口处理。

## 软件验证记录

命令：`.venv-integration/bin/python -m pytest tests/test_task_center.py -q --disable-warnings --maxfail=1`

首次扩展验收：**11 passed，14 warnings，13.31 秒**。所有状态来自临时 SQLite 和回环 HTTP/WebSocket Agent；用例执行为 XAT offline，不连接真实台架，没有读取或写入部署数据库。

覆盖点：

1. Cron 时区换算、非法表达式及非法时区拒绝。
2. 手动请求幂等：重复请求只创建一条队列，真实 Agent/XAT 产生 4 条用例结果。
3. 创建默认停用、显式启用、独立会话模拟重启恢复、合并错过的周期、停用后清除下次时间。
4. 非项目用户被拒绝，跨项目测试套目标被拒绝。
5. 排队中取消不执行，运行中取消等待真实节点完成消息。
6. 派发中断窗口明确显示待确认，人工结束按失败保存。
7. 计划目标创建真实 PlanRun/PlanRunItem，只有一次测试套队列派发。
8. 两个并发调度线程竞争同一到期任务，只有一次触发、一次入队。
9. 已被禁用的执行用户产生失败记录且不派发，下一次时间正常推进。
10. 节点连接暂不可用时保持排队，恢复后实际执行且不重复创建。

前端 TypeScript 检查通过。浏览器交互和部署迁移由总体验收统一进行；本模块单元/集成测试不替代浏览器验收。

补充回归：旧 WebSocket 队列回调不再自动领取任务中心/计划编排专属项，避免绕过派发领取和确认。加入既有超时取消、同测试套并发、断线重连幂等三项验证后，**14 passed，14 warnings，20.05 秒**；前端类型检查继续通过。
