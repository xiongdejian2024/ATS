# 测试管理扩展的 MySQL 升级验收

日期：2026-10-05。

本次使用运行中的 `ats-mysql` 容器，在名称以 `ats_management_validation_` 开头的全新临时数据库内验证。没有操作原 `ats_db`，没有启用或连接 Agent、真实模型、真实台架。容器管理凭证只在验收进程内存中使用，没有输出或保存到文件。

## 升级结果

1. 先按当前模型创建原有业务表，并插入一个用户哨兵，模拟已有 ATS 数据库。
2. 执行升级脚本的只读检查，准确返回 15 张待创建扩展表，数据库表集合未变化。
3. 执行增量升级，仅新增指定 15 张扩展表，原有用户哨兵内容保持不变。
4. `check_existing_structure` 对类型、长度、可空性、主键、唯一约束和外键的检查通过。
5. 重复执行升级返回空待创建列表，仍通过结构检查。

第一轮验收发现 MySQL 将三个 Boolean 列反射为 `TINYINT(1)`，导致直接比较 SQLAlchemy `_type_affinity` 误报。升级脚本已修为仅兼容 `Boolean` 与 MySQL `TINYINT(display_width=1)`，没有放宽为任意 Integer；修复后的完整升级已重新执行通过。

## 清理和边界

每轮验收均在 `finally` 中关闭连接并删除本轮临时数据库，随后查询 `information_schema.schemata` 确认该库不存在。原有容器、原业务数据库及原业务数据没有被停止、重建、迁移或清理。

观察到一条已有 SQLAlchemy `ProjectPermission` 关系重叠警告，不影响本轮建表、写读与清理结果。本验收证明当前新增模型和升级脚本在实际 MySQL 上可用，不等于已经对正式数据库执行升级。
