# 实时日志慢订阅隔离与恢复

## 修复范围

Agent 的日志消息先提交 `TestSuiteLog`，此前随后逐个等待浏览器 WebSocket 发送。一个不读取数据的浏览器可能阻塞同一 Agent 的后续日志、心跳、结果和完成消息。

现在每个已授权的浏览器连接拥有独立 FIFO 和唯一发送任务：

- 每个连接最多保留 64 帧、1 MiB UTF-8 JSON 数据，包含正在发送的一帧。
- 连接确认、日志、ping/pong 使用同一个发送器，保持入队顺序并避免并发写入。
- 一次广播只序列化一次，将不可变快照入队；给事件循环一次调度机会，让健康连接处理突发消息，但不等待任一浏览器网络 I/O。
- 单帧发送超过 5 秒或队列达到任一上限，就立即移除该订阅，取消发送任务并清空待发缓存。仅关闭该浏览器连接，使用 1013 和明确的“重连并重新读取历史”原因；发送错误使用 1011。
- 关闭握手最多等待 1 秒。正常退出和服务停止均回收发送及清理任务。
- 入队成功不代表浏览器收到。排队失败不伪装成功，也不保留一条仍声称连续完整的实时流。

以上默认值定义在 `backend/services/frontend_log_stream.py`。测试可构造较小限制，不修改生产配置。

## 权限与日志持久性

`/ws/client` 在注册订阅前使用 HTTP 日志接口相同的 `require_suite_access(..., "read")` 检查。继续要求有效 access JWT 和启用中的用户；项目外用户、只有写权限而没有读权限的用户、其他项目的授权、缺失测试套等不进入日志订阅表。没有新增角色或扩大既有 HTTP 访问规则。

不改变 Agent 协议、结果 ACK/outbox、任务派发或 SQL 日志存储。完整原文仍在数据库中；实时帧仍使用原有 32768 字符尾部、`endOffset` 和 `truncated` 字段。恢复时通过授权 HTTP 历史查询读取真实数据，不重建或虚构未送达帧。

## 前端恢复

独立日志页和测试套日志弹窗在服务端每次确认订阅后重新同步历史。断线、恢复中、失败和恢复后的状态显式展示；有界视窗仍只显示最近日志尾部，完整日志仍可通过既有授权 HTTP 历史接口读取（不传 tailChars）。本批没有新增完整日志下载按钮。

恢复逻辑隔离套件/执行选择、更新请求、清空和卸载；已失效的历史响应不得覆盖当前选择。历史快照与实时帧按 Unicode 字符偏移合并，避免重连重叠文本重复。

## 验证与边界

新增隔离测试覆盖：阻塞客户端与健康客户端、条数及 UTF-8 字节上限（含在途帧）、超大帧、快生产者突发、超时/异常、取消/关机清理、FIFO 与快照、不丢完整持久日志、HTTP/WS 读权限一致性。

回环集成使用真实 HTTP、WebSocket、Agent、离线 XAT 子进程和 SQLite：只向其中一个浏览器的服务器发送函数注入等待，验证另外一个浏览器继续有序收日志，四个用例结果落库并 ACK，Agent 完成，慢连接收到 1013，重新订阅后可读取完整历史。

这证明应用发送阻塞的隔离；未模拟真实 TCP 缓冲耗尽、代理或高并发压测。未运行生产 MySQL/Redis/Celery、真实台架或硬件。保持既有进程内广播模型；多进程跨 worker 广播、持续重写长 SQL 日志的成本、已连接会话的即时撤权另属独立范围。

## 回归环境隔离修复（独立提交）

全量回归首次发现两项既有迁移检查失败。按“真实 Agent/多浏览器测试 → 迁移测试”顺序可重现；单独执行迁移测试则通过。没有删除或放宽迁移断言。

诊断确认本地 SQLite 3.53.1 的连接级 schema 缓存：连接 A 创建并删除表，连接 B 重建同名含 UNIQUE 的表后，A 的首次 `PRAGMA index_list` 返回空；读取 `sqlite_master` 后，同一连接返回真实唯一索引。多个空闲池连接经历每项测试的破坏式重建，触发此现象。测试结束时连接均已归还，没有发现会话泄漏。

独立提交 `d1ff042` 在隔离库 fixture 的清理阶段调用 `engine.dispose()`，让下一项测试使用新连接，生产数据库路径及全部迁移验证保持不变。加入此清理后，“全部新日志测试 → 全部实例缺陷/测试管理升级测试”35 项通过，包含故意缺列、缺约束时必须阻止升级的负向测试。
