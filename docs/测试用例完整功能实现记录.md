# 测试用例功能补齐记录

## 第一阶段：附件、回收站、模板与关联

- 附件：复用已有文件校验/保存工具，真实上传、列表、下载和删除；按项目权限验证，10MiB/扩展名限制，随机存储名、防路径穿越、强制下载与 nosniff。默认存储 backend/uploads/cases，可用 CASE_ATTACHMENT_DIR 覆盖。
- 回收站：删除改为标记 deleted_at/deleted_by，正常列表/详情/树/治理/执行不再接受已删除用例；恢复保留附件及版本，原模块不存在时移入未规划；彻底删除拒绝有执行历史的用例，避免毁坏旧报告。
- 模板：项目模板、默认模板、字段类型和选项、必填及默认值校验；创建/编辑中的 template_id/custom_fields 与版本快照同事务。
- 关联：需求/缺陷实体与用例关联，前后置/关联用例关系并拒绝循环；自动化用例/套件/外部引用关联，内部目标必须同项目。
- 协作：关注/取消关注、讨论及删除权限、追加式变更记录。

数据库升级由主线程执行：test_cases 新增 deleted_at、deleted_by、template_id、custom_fields；新增 CaseChange、CaseTemplate、CaseIssue、CaseIssueLink、CaseRelation、CaseAutomationLink、CaseFollow、CaseComment 对应表。不删除原表、不改已有用例内容。

接口入口：/api/v1/projects/{project_id}/case-features；JSON 返回统一 APIResponse，data 内 camelCase。

隔离验收：`.venv-integration/bin/python -m pytest tests/test_case_features.py tests/test_case_governance.py -q --disable-warnings --maxfail=1`，19 passed。全部为 SQLite/临时附件，不连接真实台架。覆盖附件字节、权限/大小/格式、软删除后隐藏及恢复、彻底删除历史保护、模板必填/类型/版本、跨项目拒绝、依赖循环、关注幂等、评论权限。

## 第二阶段：V3评审与查询、导入导出

- 评审区分 single/multiple：单人模式取最后一次有效结论；多人模式按各指定人员最后一次有效结论，全部通过才通过，任一驳回为驳回。建议不覆盖有效结论。每次提交独立记入历史，允许改票，不因周期已过阻止投票。
- 支持逐条人员、批量结论（同事务校验权限）、评审复制、无有效结论时编辑、有结论后重新提审、关注、周期；重提审建立新单并保留旧轮次。项目级 autoResubmit 默认关闭，开启后内容版本变化自动重提审。
- 查询统一支持 AND/OR、多值、排除、空值、自定义字段、我的数据/关注及显式排序；列表和导出共用查询服务，非法条件返回422。JSON字段在项目候选集内计算，以保持SQLite/MySQL语义一致；大规模数据后续可按性能证据优化数据库执行。
- Excel支持选中ID、筛选、字段选择、一行一用例/一步骤一行；导入保持增量、模板字段验证与同事务快照。XMind支持标准 content.json 和旧 content.xml；标准树节点承载名称/前置/步骤/预期，附加元数据补充属性。模块树导入预检不写库。解析使用zipfile/JSON与defusedxml，限制压缩及展开体积、不落地解压、拒绝XML外部实体。
- 模块变更补项目权限、禁止跨项目父级/循环、显式null回根及层级同步；sortOrder真实持久化。统计排除回收站。

迁移增量：case_reviews新增 description、mode（旧all→multiple、any→single）、parent_review_id、start_date、end_date；case_review_items新增reviewer_ids（旧数据回退评审单人员）；新增CaseReviewEvent/CaseReviewFollow/CaseProjectSettings。
