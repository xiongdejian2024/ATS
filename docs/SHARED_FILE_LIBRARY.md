# Shared file library and retained evidence

Project members with case-read access can upload private evidence drafts; explicit “upload to project library” publishes a file. Only its uploader can list/read an unpublished draft. Case-update permission manages folders, archive/restore and case links. Actual comment, assigned review vote and plan execution authority is rechecked at each submit. Submitted evidence becomes project-visible and references are created in the same transaction.

The blue UI offers folders, filename search and 20-row paging with up to 50 selected files across pages. Case attachments link/unlink shared files. Discussions support rich text and selected files; review reasons support image uploads, shared images and attachments. Functional execution forms keep their existing private plan-image upload and can select shared images from the enclosing plan's project, including when a source case belongs to another project.

Library bytes and SHA256 are immutable. Every download checks the saved size/digest, uses private/no-store and nosniff; generic files download as octet-stream. Only decoded PNG/JPEG/GIF/WebP images have inline preview (16 million pixels per frame, 32 million total, 200 frames). HTML/SVG cannot become inline previews via a client MIME declaration. Private preview authentication uses an exact local route whitelist, never an external URL.

Directory writes lock the project then read current directory rows, including on MySQL repeatable-read. Complete file reference sets lock in sorted ID order. Archive waits on the same file locks, preserves bytes/history, and hides files from new selections. No folder/file permanent-deletion route exists. An inactive case reference is still retained history. Ordinary case attachment cleanup uses separate storage keys and cannot remove library bytes.

Existing installations run `python scripts/upgrade_file_library.py` for a preview, then explicitly use `--apply` to create the three additional tables. It does not move/modify existing attachments. New PostgreSQL private-schema export has 87 model tables. ATS continues using controller authentication, with no Supabase Data API access or grants for new tables; see [official API security documentation](https://supabase.com/docs/guides/api/securing-your-api).

`python scripts/evidence_capacity.py` only inventories expired known library/plan-image rows without any historical reference. `--archive-expired --limit 100` additionally requires `ATS_EVIDENCE_ARCHIVE_ENABLED=true` and `ATS_EVIDENCE_ARCHIVE_DIR`. Retention defaults to 30 days and the decoded-byte copy budget to 1 GiB (`ATS_EVIDENCE_RETENTION_DAYS`, `ATS_EVIDENCE_ARCHIVE_MAX_BYTES`). Copies use metadata, bounded base64 chunks, SHA256 footer and atomic gzip replacement. Sources are retained; this does not free database space or touch Agent spool. Unknown external objects from uncertain external uploads are explicitly outside this inventory; no bucket listing or deletion occurs.

Automated component/API/DDL checks are separate from pending real browser modal/navigation/refresh/narrow-screen acceptance. PostgreSQL mixed-image locking runs only against the disposable CI database. Actual optional S3 service behavior remains unaccepted until an already authorized configured service is available.
