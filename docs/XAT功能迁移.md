# XAT 功能迁移与解耦

## 目标与当前状态

把原 SAT 的 pytest 框架能力和原 ECU Simulator 的库能力迁入 XAT。最终运行、安装和验收不需要旧 `sat`、`ecu-simulator` 目录。旧目录保留作为迁移核对来源，不删除用户原文件。

这次是功能迁移。此前的外部路径适配不能证明本目标完成。进度以本文件和迁移清单为准；尚未标为完成的内容必须继续迁移与验证。

## 依赖边界

| 部分 | 目标位置 | 责任与依赖 |
|---|---|---|
| pytest 框架 | `xat/framework` | 收集、筛选、fixture、Hook、执行、结果和报告；设备 fixture 按需加载库 |
| ECU 库 | `xat/packages/ecu/src/xat_ecu` | 协议、驱动、传输、模拟、诊断、刷写、信号与业务库；不导入 pytest 或用例 |
| 用例 | `xat/cases` | 独立于库源码维护，通过公开 API 和 fixture 调用框架/库 |
| 配置和运行资源 | XAT 内各自所属目录 | 由 XAT 资源路径解析，取消依赖旧仓库路径 |

ECU 库使用独立 `pyproject.toml`、版本和测试入口。框架测试不初始化硬件。报告集成通过可注入的报告接口，避免库依赖 pytest/Allure。GitHub 按框架、库、用例路径分别运行检查，使修改和提交可以独立进行。

## 全量盘点

源码数量与范围记录在 [源码盘点](migration/源码盘点.json)。包括 SAT 框架、SDK 接口、ECU 旧库与模块化库、原用例和工具。生成代码、车型配置及驱动绑定也需要纳入迁移核对；运行日志、缓存、虚拟环境和 graphify 产物不属于功能源码。

原代码中发现明文/编码凭证。迁入时改为环境变量或用户配置注入，不上传原凭证；生产凭证、车辆配置与设备操作不会在软件验收中使用。
