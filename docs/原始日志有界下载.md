# 原始日志有界下载

实时视窗继续使用最多 20 条记录、2,000 行、512 KiB UTF-8 的浏览器缓存及虚拟滚动。计划批次历史日志也使用该视窗。折叠重复行和省略前段仅影响显示，数据库原始日志保留不变。

## 下载入口与浏览器行为

测试套日志弹窗、执行日志独立页、环境执行历史日志弹窗和计划批次日志弹窗均提供下载。

- 支持 File System Access API 的浏览器可选择“保存完整原始日志”。每次仅请求一段并等待文件写入完成，再请求下一段；不会积累完整文本或 Blob。取消、关闭弹窗、切换执行或写入失败会中止请求和文件写入，未完成文件不会作为成功结果提交。
- 所有浏览器均可选择“分段下载原始日志”。每次点击仅保存一个最多 256 KiB 的 UTF-8 文件，文件名包含快照时间，编号从 `part000001` 开始。继续点击至“快照完整”，再按编号拼接同一快照的文件字节即可恢复完整导出。未完成时有明确提示，不自动触发大量下载，也不在浏览器持久存储日志分段。
- 重新开始会建立新快照。正在执行时，下载仅包含开始下载时服务器已接收的内容；之后追加内容需重新下载。

## API 契约

对以下路径追加 `/export` 并使用 POST：

- `/api/v1/test-plans/suites/{suite_id}/logs`
- `/api/v1/test-plans/{plan_id}/executions/{run_id}/logs`
- `/api/v1/plan-orchestration/runs/{run_id}/logs`

首次请求 JSON 为 `{}`，也可通过 `executionId`、`logId` 缩小选择。后续请求 JSON 为 `{"cursor":"上一次响应的 nextCursor"}`。使用现有 Authorization 请求头及正常登录刷新机制，URL 不携带认证凭证。

标准 `APIResponse.data` 中包含 `content`、`part`、`complete`、`nextCursor`、`recordCount`、`snapshotAt` 和 `maxChunkBytes`。只有 `complete=true` 且 `nextCursor=null` 才是完整快照。失败后可用同一个输入游标重试，不能跳过失败部分。快照令牌只是签名状态，不能替代登录或项目读取权限。

- 首次仅投影最多 1,001 条元数据，不读取 LONGTEXT 正文；超过 1,000 条记录返回 413 `LOG_SELECTION_TOO_LARGE`。请在执行历史中选择单次测试套执行或指定 `logId` 分别下载，不会默默遗漏记录。
- 快照固定记录 ID、所属测试套/执行 ID 和 Unicode 字符尾部位置。相同时间戳通过 ID 稳定排序，随后出现的新执行不会混入旧下载。
- 每段最多 65,536 个 Unicode 字符，即最多 262,144 字节 UTF-8；SQL `SUBSTR` 在数据库端裁取，单个请求最多访问 32 条记录。任意长且没有换行的日志也遵守上限。游标元数据另有 512 KiB 大小上限。
- 文件为 UTF-8。每条记录增加一行时间/测试套/执行/日志 ID 标头和一行分隔符；原始正文中的空白、CRLF、重复行、中文、组合字符和 emoji 均保持原样。
- 每一段重新检查项目读取权限及批次的测试套/执行配对。游标绑定当前用户和路径选择，签名无效或选择改变返回 400，权限不足返回 403，快照一小时后过期返回 410。
- 快照记录被删除或缩短时返回 409 `LOG_EXPORT_GAP`，绝不把缺段响应标为完整。正常日志写入为追加式；此接口不实现日志正文任意改写的版本管理。
- SQLite 的文本函数会在 NUL 字符停止；含 NUL 的旧记录明确返回 409 `LOG_UNSUPPORTED_NUL`，请从原始数据库备份提取。生产 MySQL 使用 `CHAR_LENGTH` / `SUBSTR`，没有该 SQLite 文本限制。该边界在界面错误中明确显示。

## 旧 JSON 读取兼容性

无 `tailChars` 的旧 GET 继续返回原有的小响应结构。每次最多 1,000 条、合计 524,288 个正文字符；超限先返回 413 `LOG_EXPORT_REQUIRED` 并提示 `/export` 或 `tailChars`，没有悄悄截短正文。元数据检查后仍使用固定长度 `SUBSTR`，并检查长度是否发生变化，避免检查后并发追加重新造成超大分配。并发变化返回明确 409，可重试或使用快照导出。

计划批次 GET 新增可选 `tailChars`（1–32,768），返回与测试套一致的有界 `items/total/skip/limit` 视窗；原 GET 不带该参数时的小响应结构不变。

## 验证与保留边界

`tests/test_raw_log_export.py` 覆盖巨型无换行 Unicode 正文的 SHA-256 完整性、数据库正文投影、Python 峰值内存、字符/字节上限、多执行混排和同时间戳、快照后追加、空记录、权限/游标隔离、过期、删除/缩短、旧接口并发增长及 SQLite NUL。

`useRawLogDownload.test.ts` 覆盖逐段写入背压、单次分段下载、同游标重试、关闭/切换/卸载取消、重复点击、成功后重试失败、文件选择取消以及异常分段拒绝。

本改动没有自动删除或压缩服务器原始日志，没有增加数据库迁移、生产数据操作或新持久凭证。自动保留期限与清理策略尚未定义；数据库存储仍随原始证据增长，需要另行制定策略。
