# 测试用例模块开发与验收记录

日期：2026-10-05。实现方式：参考 MeterSphere 用例管理的版本、评审和筛选交互，使用 ATS 现有 Vue、Ant Design Vue、FastAPI、SQLAlchemy、Pydantic 独立实现，未引入 Java 服务或新增依赖。

## 已落地行为

- 创建、编辑、批量更新、导入、AI 调用用例创建服务时，在同一数据库事务保存用例与版本。既有无版本用例在首次修改、提交评审或删除前保留原始内容。
- 版本列表展示修改原因及内容；两个版本可按字段比较。恢复要求填写原因并提交当前版本号，过期页面会收到 409；恢复结果保存为新版本，不覆盖原版本。
- 支持对所选用例发起评审，指定一个或多个项目成员，选择全员通过或任意一人通过规则。评审绑定提交时快照，支持结论说明、讨论意见、取消及重复提交拦截。已修改或删除用例的历史评审明确标记过期。
- 列表评审状态来自当前内容对应的真实评审，旧版本通过后再次编辑会显示“重新提审”。列表支持按评审状态筛选。
- 个人筛选视图持久化到数据库，按项目和用户隔离；刷新后仍可载入关键字、模块、筛选条件、条件逻辑及状态筛选。
- 底部批量编辑、移动、复制接入真实接口。批量修改和复制为原子事务，校验全部用例和目标模块属于当前项目，跨项目目标不会造成部分修改。
- Excel/CSV 导入使用增量合并，不再把文件中缺少的既有用例隐式删除；省略的列保持原值；更新选项实际控制是否覆盖；数字编号保留前导零；导入产生版本。
- 旧 `/projects/{project_id}/cases` 系列兼容入口不再返回固定模拟成功，统一调用真实用例接口。列表、详情、创建、编辑、删除、树、导入、导出增加项目权限校验。

## 模块边界与契约

- 新模型：`CaseVersion`、`CaseReview`、`CaseReviewItem`、`CaseReviewDecision`、`CaseReviewComment`、`CaseSavedView`。只新增表，不重建旧表。
- 路由挂载：`api.v1.case_governance.router`，挂载 `/api/v1` 后实际根路径为 `/api/v1/projects/{project_id}/case-governance`。
- 创建服务：`TestCaseService.create_test_case(db, case_data, current_user_id, *, commit=True)`。AI 草稿确认可以传 `commit=False`，同事务写入版本，再由调用者提交草稿状态；调用失败回滚并记录异常堆栈。
- 保留所有既有测试执行链路。本模块没有向 Agent 下发任务，也没有执行台架或真实用例。
- 删除单个用例时保留其版本和评审快照；显式删除整个项目时新表的项目外键支持数据库级联清理。
