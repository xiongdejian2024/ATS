# 测试计划模块开发与验收记录

日期：2026-10-05。按 MeterSphere 的功能与交互独立实现，保留 ATS 品牌与 Python / Vue 技术栈，不引入 Java，也不复制 MeterSphere 源码。

## 已实现

- 计划组：新增、编辑、删除、按组筛选及未分组筛选。删除组保留计划。列表按组在数据库查询阶段分页。
- 计划执行配置：测试套串行 / 并行、执行顺序、失败后停止等待项、0–100% 通过阈值。并行受到每个 Agent 的并发容量限制。
- 执行批次：每次执行独立保存计划名称、用例、测试套及策略快照；可传幂等键防止同一调度触发重复创建。执行配置变更仅影响之后的批次。
- 真正执行：旧计划 execute 接口创建批次和原 TaskQueue；后台调度通过原 WebSocket / Agent / XAT 下发任务。计划队列统一由计划编排推进，旧完成回调不会抢先派发后续计划任务。
- 串行调度：前项结束后才入队后项。入队和派发都使用条件更新领取；派发时锁定环境行并核对容量。节点离线或禁用保持待执行状态。
- 失败停止：停止仍在等待的测试套；已经运行的测试套保留并继续回传结果。旧用例与测试套工作区继续可用。
- 取消：等待项立即取消；运行项向 Agent 发出取消指令，等待 Agent 完成确认后释放运行槽。
- 派发异常：派发已入库但超过 30 秒无法确认交付的批次进入“等待核对节点”，保留原运行槽，不自动重发。负责人确认节点未执行或已停止后才能人工终止批次。
- 手工测试：创建批次时不继承历史结果；在批次报告回填通过 / 失败 / 错误 / 跳过及实际结果说明。原手工状态接口桥接活动批次。已结束批次禁止改写结果。
- 历史与报告：原固定空数组的执行历史替换为真实批次；报告统计总执行项、通过 / 失败 / 错误 / 跳过 / 取消 / 待执行、通过率和阈值。缺少结果的已结束自动化任务计为错误，避免假成功。
- 日志：仅关联该批次下的 execution_id；报告、日志、配置、分组、执行及取消接口均检查项目权限。跨项目数据不能通过猜测 ID 读取。
- 前端：计划组工具栏；详情“执行历史与报告 / 执行配置”页签；报告查看、日志查看、取消、手工回填、JSON 导出；支持任务中心链接 `/test-plans?planId=...&runId=...` 直接打开批次报告。

通过率以本次全部执行项为分母；同一用例在两个测试套执行两次，计为两个执行项。跳过、取消、未执行都不算通过。报告只读取本批次确定性结果 ID，不读取用例的最新状态来拼装历史。

## 新增数据表

`plan_groups`、`plan_settings`、`plan_runs`、`plan_run_items`。不替换、不清空原 `test_plans`、计划用例关系、测试套或历史执行记录。测试套在批次等待、排队、运行或待确认期间禁止编辑和删除，避免快照与实际执行不一致。

## 接口入口

- `/api/v1/test-plans/{plan_id}/execute`：创建批次，支持 `suiteIds`、`notes`、`idempotencyKey`。
- `/api/v1/test-plans/{plan_id}/stop`：取消当前批次。
- `/api/v1/test-plans/{plan_id}/executions`：分页批次历史。
- `/api/v1/test-plans/{plan_id}/executions/{run_id}/logs`：批次日志兼容入口。
- `/api/v1/plan-orchestration/projects/{project_id}/groups`：组列表 / 创建。
- `/api/v1/plan-orchestration/groups/{group_id}`：编辑 / 删除组。
- `/api/v1/plan-orchestration/plans/{plan_id}/settings`：读取 / 保存策略。
- `/api/v1/plan-orchestration/runs/{run_id}`：批次报告。
- `/api/v1/plan-orchestration/runs/{run_id}/logs`：批次日志。
- `/api/v1/plan-orchestration/runs/{run_id}/cancel`：请求取消。
- `/api/v1/plan-orchestration/runs/{run_id}/resolve`：明确确认 `agentStopped: true` 后终止状态不确定的批次。
- `/api/v1/plan-orchestration/runs/{run_id}/cases/{case_id}/result`：回填手工测试结果。

调度共享接口：`start_plan_run(..., idempotency_key=None, commit=True)` 与 `advance_plan_runs(db)`。调度服务在同一事务持久化任务触发记录和计划批次后，才推进网络派发；恢复后不会重复创建已领取的批次。

## 软件验收

使用隔离临时 SQLite、随机回环端口和临时 Agent 工作目录，不连接真实台架，不访问或修改用户现有数据。

执行：

```text
.venv-integration/bin/python -m pytest tests/test_plan_orchestration.py -q --disable-warnings
npm --prefix frontend run type-check
```

12 项软件测试通过，覆盖：

1. 串行真实队列推进、幂等创建和历史互不覆盖。
2. 失败后停止后项、执行配置快照不被后续修改覆盖。
3. 并行服从节点容量、50% 阈值按真实结果生效。
4. 取消等待真实 Agent 完成确认后才释放运行槽。
5. 手工批次不继承历史通过结果，回填后独立归档且不可改写。
6. 派发中断进入待核对状态，不自动重发；人工确认后释放运行槽。
7. 等待中的测试套不可修改，同一计划禁止重叠批次。
8. 跨项目计划组和重复测试套顺序校验。
9. HTTP 分组 / 分组筛选 / 批次历史 / 精确日志，以及外部用户访问报告与日志被拒绝。
10. 禁用节点和离线节点保持排队，旧自动出队不会绕过计划编排。
11. 测试套声称完成但缺少用例结果时，报告记为错误而不是成功。
12. 真实 HTTP → 计划 → WebSocket → Agent → XAT 子进程完成 4 条软件用例，持久化报告与日志按批次准确关联。

前端类型检查通过。浏览器整体交互验收由主任务继续执行，不把类型检查等同于视觉验收。测试中的现有 Pydantic / SQLAlchemy / WebSocket 弃用警告保留，不隐瞒或当作功能失败。

## 并发与部署复审（2026-10-05）

独立复审在隔离 SQLite 中实际复现并修复了以下问题：

- 排队后执行人被禁用或撤销项目执行权限：现在派发前重新核验，不向 Agent 发命令，记录明确失败。
- 取消 / 失败停止与派发领取竞争：先持久化取消意图，再通过条件更新取消尚未领取的队列项；不能将另一会话已领取的 running 覆盖为 cancelled，继续等待 Agent 确认。
- 两位执行人同时回填不同手工用例：新增 `plan_runs.manual_revision` 并使用版本号条件更新，冲突后重新读取并合并。真实双线程测试确认两条结果均保留，最终报告冻结也校验该版本号与取消状态。
- 旧状态接口收到不存在的计划用例：先返回 404，再处理活动批次，不用 409 掩盖资源不存在。原项目 / 模块 / 仪表盘回归调整为验证恢复产生的真实批次；拒绝人工伪造该批次自动化用例通过。
- 升级脚本原先仅按表名 `checkfirst`：现在检查已有扩展表的列、类型、长度、可空约束、主键、唯一约束及外键；不兼容时在创建任何其他表之前阻断，不自动删表或重建。MySQL 的 Boolean 仅兼容反射为 `TINYINT(1)` 的情况，不把普通整数类型当作布尔。

新增 5 项计划回归后，计划模块共 **17 项通过**。升级脚本另有 **3 项 SQLite 测试通过**：只新增扩展表且保留原用户数据；缺列时阻断且不创建其他缺表；缺失幂等唯一约束时阻断。与原项目 / 模块 / 计划 / 仪表盘回归一起，共 21 项已通过。

新增任务表为空时，新的调度循环不会消费旧的台架 pending 队列，已用硬件模式命令模板和消息替身验证零派发。原 Agent 重连逻辑仍会恢复旧队列，因此部署必须先核对原队列 pending / running 与 Agent outbox，并保持硬件开关关闭；不应擅自删除或清空历史队列。

## 发送结果不确定的保守处置

2026-10-05 补强：节点最初不在线时仍保持排队；已通过在线检查并实际调用发送后，无论返回 `False` 还是抛出异常，都立即标记“等待核对节点”，保留 `TaskQueue.running` 和开始时间占用节点容量，不自动重发。后续收到该执行号的真实完成确认，可以按真实结果结束；没有完成确认时由负责人核对节点后人工终止。发送异常记录完整堆栈。

新增两项真实 Agent 回归：先把任务实际发到回环 Agent，再分别注入本地 `False` 和连接异常；连续调度多轮仍只有一次派发、一条队列，运行槽保持占用。随后 Agent/XAT 实际完成 4 条软件用例，报告按真实结果结束。计划模块累计 **19 项通过**，与任务中心一起 **32 passed，14 warnings，26.33 秒**。

## V3 功能对齐第二批：测试点、执行协作与报告

- 功能/API/场景三个分类支持层级测试点、同级排序、用例和测试套关联。关联使用独立节点 ID，因此同一用例和测试套可重复加入；列表统计、执行结果、手工回填均按关联实例区分。
- 执行时将父测试点串并行配置编译为明确的前置依赖；继承环境/资源池并允许子级覆盖。资源池使用 ATS 现有 Agent 环境，排队节点离线时从池内可用槽选择，不新增台架通道。
- 自动化仍经过 TaskQueue → 已有 Agent → XAT。消息交付不确定时保留运行槽、进入等待核对，禁止自动重发。重复测试套使用不同 execution_id，独立关联真实回传结果。
- 自动化节点可关联功能用例实例，并将本批次自动化结果映射为其结果；禁止人工覆盖自动化结果。手工串行节点必须等前序完成；失败停止会将未执行节点明确标为跳过。
- 执行人支持单个和批量分配。普通项目成员只允许回填分配给自己的实例；项目执行权限用户可管理该项目批次。按冻结步骤保存实际结果/状态/缺陷与附件，支持保存进行中的步骤。整体通过需要所有步骤通过。
- 批次评论、5MB以内附件、项目缺陷关联均持久化；附件通过权限校验下载。步骤保存缺陷当时标题/说明/状态快照，源缺陷后续变更不覆盖历史证据。
- 报告提供完整步骤、分类/结果筛选、分类统计、结论/风险/备注、JSON与真实PDF导出、脑图执行入口。复用 ECharts 用例脑图组件，没有新增脑图库。
- 分享使用随机令牌的 SHA-256 摘要存储，设置1小时至90天有效期，可随时撤销；公开入口只读报告/PDF并检查过期，不提供写入与附件下载权限。
- 计划组增加模块、标签、归档和完整复制；复制全部成员计划/用例树/测试套/策略并重映射顺序。组内冻结批次保持 group_waiting，不能被提前手工回填，待组编排释放后才入队。组执行、定时与聚合报告由计划组服务负责。

新增 `tests/test_plan_tree.py` 覆盖实例重复、树串并行、资源池切换、功能结果关联、冻结组批次、节点权限、逐步骤证据/缺陷、评论、PDF、限时分享、手工前置与失败停止、组完整复制和成员分配权限。测试不连接真实台架。API日志记录关键创建、冻结、回填、派发与完成状态，异常均保留堆栈。
